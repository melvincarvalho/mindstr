# Mindstr map format

This is the canonical description of a Mindstr map document. The README and
[SKILL.md](SKILL.md) link here rather than restating it.

Two versions exist: **0.1** (the original) and **0.2** (0.1 plus a JSON-LD context and
`parent` links). They are the same shape; a 0.2 file is a valid 0.1 file with extra
fields. See [Compatibility](#compatibility).

## Files and transport

- A map is one JSON object in a file ending `.json` or `.jsonld`. **Both extensions hold
  the same format**; `.jsonld` is preferred for pods.
- Read with `Accept: application/ld+json, application/json;q=0.9`.
- Write with `PUT` and `Content-Type: application/ld+json` for `.jsonld`, or
  `application/json` for `.json`. Pods (JSS) accept either for either extension and
  store the bytes as sent (pretty-printing may change).
- Writers should send `If-Match: <ETag from the GET>` when replacing a map, and
  `If-None-Match: *` when creating one. A `412` means someone else saved first.
- Default locations: `<pod>/public/mindstr/index.jsonld` for a person's main map,
  `<pod>/public/mindstr/<name>.jsonld` for others.

## 0.1

```json
{
  "version": "0.1",
  "nodes": [
    { "@id": "#this",   "name": "Trip",   "x": 0,   "y": 0 },
    { "@id": "#k3x9q2", "name": "Travel", "x": 230, "y": 0,   "bgColor": "#D6E8FF" },
    { "@id": "#p7m2wd", "name": "Guide",  "x": 450, "y": -40, "link": "https://example.com/guide" }
  ],
  "connections": [
    { "start": 0, "end": 1 },
    { "start": 1, "end": 2 }
  ],
  "selectedNode": 0
}
```

### Top level

| Field | Type | Rules |
| --- | --- | --- |
| `version` | string | `"0.1"`. Readers treat a missing version as `"0.1"`. |
| `nodes` | array | Required, at least one node. `nodes[0]` is the root. |
| `connections` | array | Parent → child edges, `{ "start": i, "end": j }`, where `i` and `j` are **indices into `nodes`**. |
| `selectedNode` | integer or `null` | Index of the selected node, or `null`. View state; optional. |
| anything else | any | Preserved untouched by the app (e.g. `@context`, `@type`, `name`). |

### Nodes

| Field | Type | Rules |
| --- | --- | --- |
| `@id` | string | `#` followed by 6 characters from `abcdefghijkmnpqrstuvwxyz23456789` (no `l`, `o`, `0`, `1`), e.g. `#k3x9q2`. Unique within the map. **The root's `@id` is always `#this`.** Never reuse or change an existing id. Readers should accept any unique string and repair missing or duplicate ids. |
| `name` | string | The node's text, one line. |
| `x`, `y` | number | Centre of the node in map units (≈ CSS px at 100% zoom). `y` grows downward. Any origin. |
| `bgColor` | string | Optional CSS colour, ideally a soft pastel. Renderers may ignore it on the root (the app draws the root in its brand colour). |
| `link` | string | Optional. An `http(s)` URL, or a relative reference resolved against the map's own URL. A relative link to a `.json`/`.jsonld` file is another map. A `.md` link is a document. Other schemes are not followed. |
| `collapsed` | boolean | Optional `true` when the node's branch is folded in the app. |
| `size` | number | Optional scale on the node's text and box, relative to the style for its depth. `1` (the default) is normal size; `1.25` is a quarter bigger. Renderers clamp it (the app uses 0.8–1.6) and may ignore it. Use it sparingly, to stress a few nodes. |
| anything else | any | Preserved untouched. |

### Structure rules

- **`connections` must form a tree under `nodes[0]`**: every node except the root is the
  `end` of exactly one connection, no node is its own ancestor, and every node is
  reachable from the root. The app tolerates other shapes (orphans are drawn as
  separate branches, extra parents are ignored), but layout and editing assume a tree.
- **Sibling order is connection order**: the children of a node are ordered as their
  connections appear in `connections`.
- New maps should list nodes depth-first (root, first branch, its descendants, next
  branch…) with connections in the same order.

### `@context` in 0.1

0.1 does not require a context, and the app does not add one: it preserves whatever
top-level fields a map already has. Maps generated by the cos tools carry
`{ "@vocab": "https://mindstr.org/ns#" }`; in 0.1 that is a placeholder with no defined
vocabulary behind it.

## 0.2

0.2 adds three things and changes nothing else (`x`, `y`, `bgColor`, `connections` and
the layout are as in 0.1):

1. a JSON-LD `@context`, so the document is a real graph;
2. `parent` on every non-root node, naming its parent by `@id`;
3. `"version": "0.2"`.

```json
{
  "@context": {
    "@vocab": "https://mindstr.org/ns#",
    "link": { "@type": "@id" },
    "parent": { "@type": "@id" }
  },
  "version": "0.2",
  "nodes": [
    { "@id": "#this",   "name": "Trip",   "x": 0,   "y": 0 },
    { "@id": "#k3x9q2", "name": "Travel", "x": 230, "y": 0,   "parent": "#this", "bgColor": "#D6E8FF" },
    { "@id": "#p7m2wd", "name": "Guide",  "x": 450, "y": -40, "parent": "#k3x9q2", "link": "./guide.jsonld" }
  ],
  "connections": [
    { "start": 0, "end": 1 },
    { "start": 1, "end": 2 }
  ],
  "selectedNode": 0
}
```

### The context

- `@vocab` is `https://mindstr.org/ns#`: every plain key (`name`, `x`, `y`, `bgColor`,
  `collapsed`, `size`, `nodes`, `connections`, …) becomes an IRI in that namespace. It is the
  namespace the cos-generated 0.1 maps already use, and mindstr.org can publish a
  vocabulary document there later. (`urn:solid:` was considered and rejected: it has no
  owner, and generic terms such as `name` or `parent` would collide with other apps'
  meanings.)
- `link` and `parent` are typed `@id`, so their values are IRIs. Relative values resolve
  against the document's URL by normal JSON-LD rules — the same resolution the app
  already does for links.
- Writers that find an existing `@context` keep it and add only the missing pieces
  (`@vocab` if absent, and the `link` / `parent` typing). A string or array context gets
  an object with the two typings appended.

### `parent`

- Every node except the root has `"parent": "<@id of its parent>"`, e.g. `"#this"`.
- Because node ids are fragments, a node has a full IRI:
  `https://alice.example/public/mindstr/trip.jsonld#k3x9q2`. Links can therefore point at
  a node in another map: `"link": "./other.jsonld#k3x9q2"` (the app opens that map with
  the node selected).
- Readers may accept a full IRI for `parent` and match it by its fragment.

### Which edges win

A 0.2 file carries the tree twice: `connections` (by index) and `parent` (by id).

- **Writers** always emit both, and always compute `parent` from `connections`.
- **Readers** use `connections` when present and valid. If `connections` is missing or
  empty, they build it from `parent` (in node order). **If both are present and
  disagree, `connections` wins, and `parent` is rewritten on the next save.** This
  covers a 0.1 app that re-parents a node in a 0.2 file: it updates `connections` and
  carries the old `parent` along untouched.
- RDF consumers only see `parent`: in RDF, `nodes` is an unordered set and index-based
  `connections` have no meaning. That is consistent with the rule above as long as
  writers rewrite `parent` on every save.
- Sibling order is still connection order; readers that only use `parent` fall back to
  node order.

Deliberately not in 0.2: `@type` on nodes, schema.org aliases for `name`, a hosted
context, and any change to `x`, `y` or `bgColor`.

Optional node fields that readers can ignore, such as `collapsed` and `size`, don't change
the version: an app that doesn't know one preserves it and draws the node as usual.

## Compatibility

| Reader \ file | 0.1 file | 0.2 file |
| --- | --- | --- |
| **0.1 app** | as before | works: unknown fields are preserved, `connections` is used, `parent` and the context are carried along untouched (`parent` may go stale after re-parenting) |
| **0.2 app** | opens as before; derives `parent` internally from `connections`; **saves it back as 0.1, unchanged** | native: reads `connections` (or `parent` if `connections` is absent), saves `parent` rewritten from `connections` |

What the app writes:

- **Saving an existing map** keeps its version: a 0.1 map is saved as 0.1 (no `parent`, no
  added context); a 0.2 map is saved as 0.2.
- **New maps**, maps opened from Markdown or text outlines, and blank drafts are created
  as 0.2.

## Outlines

Plain-text outlines (Markdown headings, `-`/`*`/`+`/`1.` bullets, indentation,
`[text](url)` for links) convert to and from the same tree. They carry names, links and
structure only — no positions or colours. The app reads them on paste, "Add from
outline…" and Open file, and writes them with "Copy as outline". This is the simplest
format for LLMs and other tools to produce.
